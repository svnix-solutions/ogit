# CLAUDE.md

Guidance for Claude Code in this repository.

## What this is

oGit: a Git Smart HTTP server with users, sessions, per-repository access control and pluggable repository storage (local filesystem or S3-compatible). Go module `github.com/labbs/ogit`. Development happens on the `refactor` branch; `main` holds an older, unrelated layout (`internal/`, `pkg/`).

## Commands

```bash
go build -o ogit ./cmd/cmd.go                 # CGO is required (gorm sqlite driver)
./ogit migration -c config.yaml                # must run before the server; the server does not migrate
./ogit server -c config.yaml
air                                            # live reload: builds tmp/main, runs start.sh (migration + server)

go test -race ./...                            # everything, including end-to-end tests on fake S3; no Docker
go test -race -tags=integration -run MinIO ./...   # MinIO variants via testcontainers (Docker must be running)
OGIT_TEST_DB=postgres go test -race -tags=integration ./interfaces/cli/server/   # whole e2e suite on Postgres
go test -race -tags=integration -run Mailpit ./...   # real SMTP via a Mailpit container
go test -race -tags=integration -run Redis ./...     # Redis cache, incl. two servers sharing it
go test -run 'TestGitHTTPAuthorization/s3_fake/non_member' ./interfaces/cli/server/   # single subtest

npm --prefix web ci && npm --prefix web run build   # web UI into web/dist (embedded by go build)
npm --prefix web run dev                       # Vite on :5173, proxies /api to a server on :8080
npm --prefix web run typecheck && npm --prefix web test
```

There is no Makefile. CI (`.github/workflows/pr.yaml`, PRs into `main` and `refactor`) runs a web job (npm ci, typecheck, vitest), then gofmt, `go vet`, `go test -race`, the UI build and a static Linux build that embeds it, and a separate job running the MinIO and Mailpit tests and the e2e suite on Postgres. Keep `gofmt -l .` empty.

## Configuration

`config.Config` is a struct filled by the flags in `infrastructure/config/*_flags.go` and passed by value. Each flag resolves CLI > env var > YAML (`-c`, default `config.yaml`; a missing file is silently ignored). `config-example.yaml` documents every key, and `./ogit server --help` lists the flags and env vars.

To add a setting: add a field to `config.Config`, add a flag with `cli.EnvVar(...)` and `altsrcyaml.YAML(...)` sources to the matching `*_flags.go`, and include that function in `getFlags` in `interfaces/cli/server/server.go` (and in the migration command if it needs it). Flag names and aliases must be unique; `TestFlagNamesAreUnique` enforces this.

Startup rules: `session.secret_key` must be ≥ 32 bytes, or empty (a random per-process key is generated, with a warning). Only `sqlite` and `postgres` dialects, and only `local` and `s3` storage, are implemented, although flag help mentions mysql and gcs.

## Auth model

- **API sessions**: login returns a JWT (HS256 only) that references a `session` row. fiber-oapi validates it on every `/api/v1` route unless `Security: "disabled"` is set (login, register, health). `SessionApp.ValidateToken` puts the session ID into `AuthContext.Claims[application.SessionIDClaim]`. `POST /api/v1/auth/logout` deletes that row, so the JWT stops validating although it has not expired. A cron job (`infrastructure/jobs`) deletes expired sessions every minute.
- **Email verification** (`application/email_verification.go`, off by default): when `registration.require_email_verification` is on, `Authenticate` refuses unverified users (after the password check) with `ErrEmailNotVerified` (403). `setupDeps` refuses to start without `smtp.host`, `smtp.from` and `http.public_url`. Links are single-use and stored hashed, one pending per user (`email_verification`). Resend always answers 200 and is rate-limited. The link is a plain Fiber GET (HTML page), next to the `POST /api/v1/auth/verify` JSON endpoint. Mail goes through `mail.Sender`: `SMTPSender` in production; tests set `srv.deps.AuthApp.Mailer` to a `mailtest.Recorder` or use `mailtest.StartMailpit` (integration tag).
- **Browsing** (`gitbrowse`, `BrowseApp`): go-git's `git.Open` can't be used (S3Storer is a `storer.Storer`, not a `storage.Storer`), so everything works on objects. `SplitRefPath` resolves `<ref>/<path>` by the longest branch or tag that prefixes it (refs contain slashes). Reads are open to anyone on public repositories, `GET /repository/:id` included (role `none` for anonymous). **Raw files** must never render as HTML on the site's origin: text is `text/plain`, a few image types inline, the rest downloads, always with `nosniff` and a `sandbox` CSP (`TestBrowseRepositories` checks an HTML file). Raw and archive auth is git's: Basic token via `AuthorizeGit`, else the session cookie, else anonymous. `TestBrowseRepositories` runs on local and fake S3.
- **Pull requests** (`application/pull_request_app.go`, rules at the top): numbers per repository (`pullRequestPers.Create` takes MAX+1 in a transaction and retries on the unique index). `gitmerge` merges at file level only (a path changed differently on both sides is a conflict; no line merging) and builds objects in memory, written as one pack by `Write` only when the merge succeeded. The target ref moves with `CheckAndSetReference` against the tip the merge used (`ErrTargetMoved`; `TestConcurrentMerges`). Merged and closed pull requests record both tips so their diff survives branch moves. Authors are nullable: deleting a user keeps their pull requests (UserPers.Purge clears `author_id`/`merged_by_id`). fiber-oapi only fills string path params: `:number` is parsed in the handler.
- **Reviews** (`application/pull_request_review.go`, rules at the top): approvals are computed on every read from the reviews (latest per reviewer, developer+ at that time, not the author); there is no stored "approved" flag. Notifications go through `NotificationApp.Notify` (`application/notification_app.go`, rules at the top): callers build participants with reasons (`Recipients`, the strongest reason wins) and, for new threads, watch levels; the inbox row (`notification`, one per user and thread, upserted) is written at once, emails go out in a goroutine per the user's `notification_preference` (tests wait with `assert.Eventually`). Recipients are filtered by `CanUserAccess(read)`, so an @mention can't leak a private repository; `ignore` watchers and muted threads are dropped. Failing statuses reach pull request authors through `StatusApp.Failed` → `PullRequestApp.StatusFailed`. SQLite does not enforce the review/comment/label cascades: `repositoryPers.Purge` and `labelPers.Delete` delete those rows explicitly. Requested reviewers (`pull_request_reviewers.go`, `pull_request_reviewer`) are removed by `SubmitReview`, and count as participants for notifications.
- **Rate limits** (`infrastructure/ratelimit`, rules in `config.RateLimit`): fixed windows in memory or Redis, fail-open. `Guard.ClientIP` is the only client-IP source for limits: it trusts `X-Forwarded-For` only from `http.trusted_proxies` and reads it right to left (Fiber's `c.IP()` would take the client-controlled leftmost entry). Failure-only rules use `Check` before and `Fail` after (login, password change, git Basic tokens); budgets use `Allow` (API middleware after websession, keyed by the JWT's user id when its signature verifies; git per token hash, user, SSH key or IP). Tests run with limits off (the config struct's zero value); `withLimits` enables small ones.
- **Public routes with an optional session** (`interfaces/http/v1/site`): fiber-oapi has no optional auth, so these are `Security: "disabled"` and read the bearer (or the cookie, which the middleware turned into one) themselves; an invalid one means anonymous. `ViewNamespace` hides a group unless the caller is a member or one of its repositories is visible.
- **Web UI sessions** (`interfaces/http/websession`): `POST /api/v1/auth/session` is login with the JWT in an HttpOnly `ogit_session` cookie (never in the body) plus a readable `ogit_csrf` cookie; `DELETE` logs out. `websession.Middleware`, registered on `/api/v1` before the routes, turns the cookie into an `Authorization` header when there is none, so fiber-oapi and handlers need no change. Cookie-authenticated non-GET requests must send `X-CSRF-Token` = `ogit_csrf` (403 `CSRF_FAILED`). The public auth POSTs (login, register, verify) ignore cookies, so a stale one never blocks logging in. Bearer requests are never CSRF-checked.
- **Git over HTTP**: HTTP Basic, username = token name, password = personal access token (`POST /api/v1/user/token`). Tokens are `ogit_<64 hex>`. Only `application.HashToken` (SHA-256) is stored; lookups hash the presented value. Token types: `user` (scoped by repository roles) and `repository` (bound to one repo).
- `AuthApp.AuthorizeGit` decides, and `interfaces/http/git/auth.go` maps the result: `ErrGitUnauthenticated` → 401 + `WWW-Authenticate` (git prompts), `ErrGitNotFound` → 404, `ErrGitForbidden` → 403. Anonymous callers may only read public repos.
- **Two-factor authentication** (`application/two_factor.go`, rules at the top; TOTP in `helpers/totp`, secrets sealed by `helpers/secretbox` with `security.encryption_key`): login with 2FA returns a `login_challenge` (hashed token, 5 minutes, 5 attempts) instead of a session; `/auth/login/2fa` and `/auth/session/2fa` complete it. A TOTP step is accepted once (`UseStep` is a conditional UPDATE); recovery codes are SHA-256'd and single-use. **Sudo**: `session.sudo_until` (set at login and by `/auth/sudo`); sensitive handlers call `TwoFactorApp.RequireSudo(authCtx)` first (`SUDO_REQUIRED`, which the UI's `api()` turns into a confirm dialog and a retry). New sensitive endpoints must do the same. Tests: `TestTwoFactor*`, each rule mutation-checked. **Security keys/passkeys** (`application/webauthn.go`, rules at the top; go-webauthn v0.15.0, pinned because later versions raise the go directive or upgrade x/crypto): the relying party is `http.public_url`'s host (none: no keys); 2FA is on with a confirmed TOTP *or* a key. Every ceremony's session data is a `webauthn_ceremony` row bound to its user and kind, taken once (`TakeCeremony`). Passkey sign-in is discoverable login with user verification required. Tests use a software authenticator (`softKey` in `webauthn_test.go`) that signs real ES256 assertions, so keep testing new flows with it. **Requiring 2FA** (`application/two_factor_required.go`, rules at the top): site-wide is `security.require_2fa` or the `site_setting` row from the admin page; `TwoFactorApp.MustEnroll` is checked by the `/api/v1` gate (`interfaces/http/two_factor_gate.go`, sessions only, a no-op unless required), `TokenApp.Authenticate` (API tokens), `authorizeGit` (git tokens) and `AuthorizeSSHAs`. `AdminApp.RequireAdmin` needs 2FA (the tests' `promote` adds a confirmed TOTP row). Groups: `group.require_two_factor`; every group-derived access goes through `RepositoryApp.usableGroups`/`groupUsable` (memberships, namespace role, dashboard, creating in the group): use them for any new group-based check. `AuthApp` holds copies of `RepositoryApp` and `TokenApp`, so their hooks are set before `NewAuthApp`.
- **Login never reveals whether an account exists**: an unknown email and a wrong password both return 401 `INVALID_CREDENTIALS` and both pay for one bcrypt comparison (`dummyPasswordHash`). Account state (disabled, unverified) is only reported after a correct password. Keep this for any new credential check. `TestLoginDoesNotRevealAccounts` checks the answer and the timing.
- **SSH keys** (`application/ssh_key_app.go`, rules at the top): only public keys are stored. Accepted: ed25519, ECDSA, RSA >= 3072, and FIDO sk- variants. Users manage their own keys (an email when one is added, if SMTP is configured); maintainers+ manage deploy keys; admins list and revoke.
- **Repository lifecycle** (`application/repository_lifecycle.go`): owners rename, change visibility, archive and delete (`?confirm=<slug>`); maintainers+ edit the description. Archived repositories refuse pushes (`ErrGitArchived`, checked after authorization) on HTTP and SSH. Owner and admin deletion share `purgeRepository` (rows, then git data).
- **Site admins** (`application/admin_app.go`, rules at the top): `AdminApp.RequireAdmin` re-reads the user on every call (role `admin` and active). Admins get no implicit repository access; `SetRepositoryOwner` makes it explicit. The API keeps at least one active admin (`ErrLastAdmin`). `ogit admin promote|demote` (`interfaces/cli/admin`) writes the role directly and is the bootstrap and recovery path. Deleting a user is refused with `OrphanError` (listing repos and groups) while they solely own a repo or own a group. `SessionApp.ValidateToken` rejects sessions of disabled users, and disabling also deletes their sessions; tests check each layer separately. Admin actions log `"component":"audit"`.
- **Webhooks** (`application/webhook_app.go`, rules at the top; payloads in `webhook_payload.go`): maintainers+ manage them; events are rows in `webhook_delivery`, enqueued synchronously by the action (`emit` never fails it) and sent by `WebhookApp.Run` on every server; `Claim` is a conditional `UPDATE` on `locked_until`, so each delivery is sent once (`TestWebhookDeliveredOnce`). Push events come from `AuthorizeGitAs`' pusher plus `AppliedUpdates(req, report)` on HTTP and SSH, and from PR merges; `Pushed` also sends `pull_request` synchronize for open PRs whose source branch moved. PR, review and comment events (`webhook_pull_payload.go`) are emitted by `PullRequestApp` after each change succeeds; deliveries run in parallel, so tests must not depend on their order (`find`). The SSRF guard (`infrastructure/webhook`) checks the dialed IP in `Dialer.Control`, not the URL; tests reach 127.0.0.1 only through `webhooks.allowed_hosts`. Tests call `DeliverDue` instead of running the worker.
- **Forks** (`application/fork.go` and `pull_request_fork.go`, rules at the top): a fork is `InitRepository` plus `helpergit.CopyObjects` (one pack of what the destination lacks) plus the refs. `repository.fork_of_id` is nulled when the original goes; `pull_request.source_repository_id` deliberately has no foreign key, because NULL means "this repository". Fork pull requests read their head from `refs/pull/<n>/head` in the target (`headTip`), kept current at creation, on pushes to the fork (`SourcePushed`, from the HTTP/SSH handlers) and lazily on `Get`. The preview uses the read-only `helpergit.Overlay`. Maintainer edits go through `AuthApp.userGitAccess` → `ForkEdits` (`EditableBranches`), and `LimitPush` restricts the push to those branches, before branch protection.
- **Issues** (`application/issue_app.go`, rules at the top): numbers come from `repository.last_number`, shared with pull requests (`persistence/numbers.go` `nextNumber`, inside the create transaction; the UPDATE serializes concurrent creates, `TestIssueNumbersAreSharedWithPullRequests`). Never compute numbers with MAX(number) again. `repository.has_issues` has no gorm default: `RepositoryApp.Create` sets it true. SQLite does not cascade: issue rows are deleted explicitly with the repository, issue labels with the label, and user purges clear `author_id`/`closed_by_id`. Assignees (`issue_assignee`, `pull_request_assignee` via `domain.AssigneePers`) and milestones (`application/milestone_app.go`, rules at the top) apply to issues and pull requests alike; deleting a milestone nulls `milestone_id` first, and deleting a user drops their assignments. `PullRequestApp.Merge` calls `IssueApp.CloseFromPull` for merges into the default branch (`ClosingReferences`).
- **Branch protection** (`application/branch_protection.go`, rules at the top; matching and specificity in `domain/branch_protection.go`): owners manage rules, developers+ read them. Pushes are checked per ref inside receive-pack: `GuardedReceivePack(st, ep, check)` calls the `RefCheck` from `ProtectionApp.PushCheck` in `SetReference`/`RemoveReference`, after the pack is stored, so a refused ref is reported as `ng` while the others apply (HTTP and SSH both pass it). Merges use `PullRequestApp.mergeBlocked`, which is shared by `can_merge`/`merge_blocked` in the view and by `Merge`, the only one that logs bypasses. Every rule has a mutation-checked test in `branch_protection_test.go`.
- **Releases** (`application/release_app.go`, rules at the top): the table is `repository_release` (`release` is an SQL keyword). The caller is a `StatusCaller` (session or token, `optauth.Caller`), so CI tokens can write; `canWrite` decides. Drafts create no tag and send no events. Publishing creates the tag (`ensureTag`, with `ReferenceCreator` when the storage has it), and that is a push event. `TagCheck` is the hook for protected tags (`ProtectionApp.ReleaseTagCheck`). **Assets** (`application/release_asset.go`, rules at the top): files are `storage.Config.PutAsset` blobs keyed by asset id inside the repository's storage (`<key>.git/release-assets/<id>`, S3 `.../release-assets/<id>`), so repository deletion takes them; rows are deleted with the release (SQLite does not cascade) and the files after. Uploads are plain Fiber routes (not fiber-oapi) reading `BodyStream`: the server runs with `StreamRequestBody`, and `interfaces/http/body_limit.go` restores the 4 MB BodyLimit on every route except the upload paths and `git-receive-pack` (`streamedRoutes`); keep new upload routes in that regexp. On those routes the connection is closed after the answer: a handler that answers without reading the whole body would otherwise have fasthttp parse the rest as the next request (`TestStreamedBodiesDontDesync`). The limit is counted while streaming (`releases.max_asset_size`, 0 = 100 MB). Downloads are always `application/octet-stream` attachments (never the uploaded type) and count. Releases and assets also have a random numeric `api_id` (< 2^53) for `ghcompat` (`/api/v3/repos/.../releases`, uploads under `/api/uploads`): go-github parses ids and user ids as integers, so those payloads use `api_id` and users without an id. **Protected tags** (`application/protected_tag.go`, rules at the top; `ProtectionApp.Tags`): checked in `PushCheck` for `refs/tags/*` and on releases that create a tag; owners bypass moves and deletes (audit log). UI: `web/src/pages/repo-releases.tsx` (uploads through `XMLHttpRequest` for progress, `uploadAsset` in `lib/releases.ts`, with the CSRF header) and `repo-protected-tags.tsx`; `/api/v1/instance` exposes `max_asset_size` so the UI refuses oversized files before sending them (the server closes the connection on those, so the browser would only see a network error).
- **Git LFS** (`application/lfs.go` and `lfs_locks.go`, rules at the top; HTTP in `interfaces/http/lfs`): under `/<owner>/<repo>.git/info/lfs`, registered before the raw routes. Auth is git's (`AuthorizeGitAs`) plus HMAC LFS tokens (`LFSApp.Token`, key derived from `session.secret_key`, one hour, one repository, download or upload) handed out by the batch API and SSH `git-lfs-authenticate` (needs `http.public_url`). Objects live in the storage backend (`PutLFSObject`/`OpenLFSObject`/`StatLFSObject`: `<key>.git/lfs/objects/aa/bb/<oid>`), verified while streamed; the PUT route is in `lfsUploadRoute` (`body_limit.go`). Downloads fall back to the fork chain (`sources`, read access checked per repository); uploads and verify only look at the repository itself. Locks are enforced in pushes by `LFSApp.PushCheck`, chained after branch protection (`application.Chain`) on HTTP and SSH: it compares each locked path's entry between old and new tips (a new branch against the default branch), not the full diff. Browse/raw/archives detect pointers (`gitbrowse.ParsePointer`, the canonical format only) and serve content through `BrowseApp.LFSFor`. Tests use the real `git-lfs` (`lfsCLI`, filters installed in the isolated HOME).
- **Actions** (`application/actions_app.go`, rules at the top; workflow parsing in `actions_workflows.go`): the server parses workflows itself with yaml.v3 (name, `on`, runs-on labels) and never runs act code: act's `model.Workflow.On()` calls `log.Fatal` on a bad `on:`. A run (`action_run`, numbered by `repository.last_run_number`) is one workflow for one event, claimed whole by one runner (`ClaimRun`, a conditional UPDATE; `TestActionsConcurrentClaims`); `action_job` rows are what the runner reports, `action_log` holds log chunks. Pushes queue runs through `WebhookApp.Pushed` → `ActionsApp.Pushed`. Runners (`action_runner`, scopes site/group/repository, token `ogitr_`) register with one-time registration tokens (`ogitreg_`, an hour) and speak the JSON protocol in `interfaces/http/runner` (`/api/actions/runner/{register,fetch,runs/:id/state,runs/:id/log}`; fetch long-polls). Job tokens (`ogitj_`, hash on the run while it runs) are accepted by `AuthorizeGitAs` (`authorizeJobToken`: its repository, read only) and, as `token`/`Bearer`, by the raw package's `/api/v3/repos/.../tarball|zipball/<ref>` (actions/checkout without git). The runner is `infrastructure/actrunner` + `interfaces/cli/runner` (`ogit runner register|run`): act v0.2.89 with `LogOutput`, our job logger (`reporter`: log chunks and job states via a logrus hook on `jobResult`) and an action cache that tries this server, then github.com. Stale runs fail after 10 minutes (`ActionsApp.Watch`, which also runs due schedules). Docker tests: `TestActionsRunnerDocker` (integration tag, alpine). Other events (`actions_events.go`, `actions_dispatch.go`, rules at the top): `WebhookApp.emit` calls `ActionsApp.Event` for every webhook event (pull_request, issues, issue_comment, release), so `Pushed` emits same-repository `synchronize` whenever Actions is on, webhooks or not; create/delete come from `Pushed`. pull_request runs test `refs/pull/<n>/merge` (written with `gitmerge`), post statuses on `StatusSha` (the head); fork runs are `from_fork` (no secrets, `contents:read`) and first-time contributors' `needs_approval` (queued but never handed out until `Approve`; the API shows `waiting`, no new status value, so no CHECK change). Job tokens: `TokenApp.Authenticate` turns them into a synthetic repository token (`ActionsApp.JobToken`, scopes from the run's `permissions`), so every route taking repository tokens takes them; git pushes need `contents:write` and are `Pusher.JobToken` (no runs). Schedules (`action_schedule`) are replaced on default-branch pushes and claimed once with a conditional UPDATE on `next_run_at`; times are UTC because SQLite compares them as text. Secrets (`actions_secrets.go`): `security.encryption_key` via `TwoFactorApp.Box`. Per-job statuses go through `StatusApp.Post` (no caller), sharing `post` with `Create`. UI: `web/src/pages/repo-actions.tsx` (runs list, run page with logs polled every 2s through `?from=`, `PullRuns` on the pull request page), `lib/actions.ts`, and `components/actions-settings.tsx` shared by repository settings, group and admin pages; the tab shows when `GET .../actions/workflows` says `uses_actions`. Badges are served by the raw package (`badge.go`, git's auth, escaped SVG). Artifacts (`application/actions_artifacts.go`, rules at the top; `interfaces/http/artifacts`): GitHub's v4 Twirp service at `/twirp/github.actions.results.api.v1.ArtifactService/` with `ACTIONS_RUNTIME_TOKEN` (an HS256 JWT whose `scp` names the run; clients read it unverified, the server checks it and that the run still runs) and HMAC-signed upload/download URLs (bound to the operation, an hour). Uploads are Azure-style blocks stored separately and assembled in block-list order (the SDK uploads them in parallel); blocks are recorded in `action_artifact_block` so abandoned uploads are cleaned up (sweep: expired, or unfinished for a day). Files live in the storage area `artifacts` (`storage.Config.PutFile/OpenFile/DeleteFile`, areas generalized from release assets). Runs and artifacts have numeric `api_id`s (GITHUB_RUN_ID, the REST API in `ghcompat/artifacts.go`). GitHub's own artifact actions refuse non-GitHub hosts (`isGhes()`), and act resets `GITHUB_*` for actions after a step's `env:`, so the runner embeds its own `ogit/upload-artifact` and `ogit/download-artifact` (`infrastructure/actrunner/shims`, Node 20, no dependencies; served by the action cache as a bare repo, `writeShim`). act only passes `ACTIONS_RUNTIME_URL/TOKEN` to jobs when `ArtifactServerPath` is set, so the runner sets it. Cache (`application/actions_cache.go`, rules at the top; `interfaces/http/actionscache`): `@actions/cache` falls back to the v1 REST API on any host it takes for GHES (everything but github.com), so oGit serves v1 under `/_apis/artifactcache` (lookup, reserve, PATCH chunks at `Content-Range` offsets, commit) with the runtime token; chunks are stored separately (`action_cache_chunk`) and assembled on commit, which checks they cover the size end to end; downloads are signed URLs with HEAD and byte ranges (`storage.OpenFileRange`). Eviction keeps the most recently used entries that fit (`evict`). Runs claimed but never acknowledged (heartbeat still at the claim) go back to the queue after 2 minutes (`Requeue`), so a runner stopped mid long-poll doesn't strand a run.
- **Repository tokens** (`application/repository_token.go`, rules at the top): `token.type = 'repository'`. On the API they act as the principal `repo-token:<repository id>` (`domain.RepoTokenPrincipal`): `GetUserEffectiveRole` makes it a reporter of that repository only, before any membership query (Postgres would reject the non-UUID). Only repository-scoped read handlers use `optauth.Reader`; elsewhere tokens are anonymous. Use `domain.IsPerson` wherever "signed in" matters (comments, reviews, `?mine=`). Statuses created by a token have no creator. `tokenPers.Delete` deletes by id: callers check ownership.
- **Commit statuses** (`application/commit_status.go`, rules at the top): GitHub's statuses API under `/api/v1/repository/:identifier/statuses` and, for CI plugins, `interfaces/http/ghcompat` (`/api/v3/repos/<owner>/<repo>/statuses/<sha>`, `/commits/<ref>/status`; releases too, see Releases). These routes accept personal access tokens (`optauth.Caller`: `token <pat>`, `Bearer ogit_...`, Basic; `TokenApp.Authenticate` looks the token up by hash alone), so they are `Security: "disabled"`; bad tokens count as failed logins. `write:status` posts without git access. `target_url` is shown as a link: http(s) only. Required contexts live on branch protection rules and are checked in `mergeBlocked`.
- **Never disclose private repositories**: callers who can't read one get the same 404 as for a missing repo (git routes and `RepositoryApp.GetRepositoryForUser`). Keep that for new endpoints.
- Roles (`domain/member.go`): reporter = read, developer = write, maintainer/owner = admin. The repo creator becomes owner. `RepositoryApp.GetUserEffectiveRole` is the max of the direct membership and every group membership (via `group_member`).
- **Membership rules** live in `application/repository_members.go` and `application/group_app.go` (each file starts with a summary). Owners do anything; maintainers are capped at developer (`checkCanManage`). Groups are at most maintainer on a repo and can only be added by their members. Repos keep at least one owner (`domain.ErrLastOwner`, enforced in `repositoryMemberPers` inside a transaction, with `FOR UPDATE` on postgres; `TestLastOwnerConcurrentDemotion` shows the lock is needed). Groups have exactly one owner (`group.owner_id` mirrors the owner's `group_member` row) and change owner only through `TransferOwnership`.
- Application errors (`application/errors.go`) map to HTTP statuses in one place, `interfaces/http/v1/apierror`. Use `apierror.From` in new handlers. Path params in request DTOs are tagged `json:"-"`, because fiber-oapi parses the body after the path and a body field could otherwise override them.

## Storage

Repositories are addressed by **path, `<namespace>/<slug>`** (`application/namespace.go`, rules at the top). The namespace is a username or a group name (one shared set of names: `domain.ValidNamespaceName`, reserved words, and `checkNewNamespace` refuses a group named like a user and vice versa). It is stored on the row (`repository.namespace`, plus `owner_type`/`owner_id`) because usernames and group names never change; slugs (`slug.Make(name)`, which also prevents path traversal) are unique per namespace. Git URLs are `/<namespace>/<slug>.git` (routes `/:owner/:repo/...`; flat `/:repo/...` URLs answer a 404 explaining the new form, as does SSH). The API takes an id or the path with `/` URL-encoded (`repoid.Split`); `RepositoryApp.GetRepository(id, path)` and `SplitPath` are the only parsers. **Storage is keyed by `repository.storage_key`, not the path**: the id for new repositories, the original slug for those created before renames existed. Never pass a path to `storage.Config`. `AuthorizeGit` / `AuthorizeSSH` return the resolved repository, and the HTTP git handlers read its storage key from `ctx.Locals(storageKeyLocal)`. Renames and transfers (`Transfer`, `AdminApp.TransferRepository`) keep the old path as a `repository_redirect` (namespace, slug), resolved inside `GetRepository`; a repository created at that path takes it over.

- **Namespace roles** (`RepositoryApp.namespaceRole`, part of `GetUserEffectiveRole`): a user owns the repositories in their namespace; a group's members get their group role on the group's repositories (owner→owner, maintainer→maintainer, member→developer). Repositories created in a group's namespace get no owner row; the group owner is their owner. Creating in a namespace (and transferring into one) needs your own namespace or group maintainer/owner (`namespaceForCreate`); groups you are not in are NAMESPACE_NOT_FOUND.
- Users and groups whose namespace still holds repositories can't be deleted (`OrphanError` / `ErrNamespaceNotEmpty`).
- The `20261025100000_namespaces` migration moved existing repositories under their oldest user owner and dropped flat redirects; it rebuilds the `repository` table on SQLite.

- **local**: `<path>/<storage_key>.git`, created by committing a README in a temp repo and cloning it bare, on `main`. `GetStorer` wraps go-git's filesystem storer (`local/refs.go`): refs are written to a temp file and renamed (go-git truncates in place), and a missing object makes it list the packs again once, because go-git lists them only on the first read and another request may have written a pack since (`TestConcurrentMerges` on Postgres hit both).
- **s3**: keys `repositories/<storage_key>.git/{config,HEAD,refs/...,objects/pack/pack-<sha>.{pack,idx}}`. The repo exists if `HEAD` exists. The client uses path-style addressing and `WHEN_REQUIRED` checksums for non-AWS S3. `S3Storer` is a hand-written go-git `storer.Storer`:
  - **Objects** (`s3/packs.go`): `PackfileWriter` stages a pushed pack in a temp file, indexes it, uploads the `.pack` and then the `.idx` (an index means a complete pack). `state()` lists the packs once per storer, i.e. once per request, so servers sharing a bucket see each other's pushes. Packs are read by ranged GETs of 4 MiB blocks (`s3/blockfile.go`). New repositories are packed too (`createInitialCommit`).
  - **Loose objects** (`objects/xx/...`, the layout before packs) are still read, but only if the listing found some (`hasLoose`). `S3Storage.Repack` / `ogit storage repack` (`interfaces/cli/storage`) packs them, checks every hash is in the new pack, and only then deletes them (a request that listed before the new pack existed can then miss an object).
  - **GC** (`s3/gc.go`, `ogit storage gc`, command only): merges small packs geometrically (`mergeSplit`, factor 2, like `git repack --geometric`) and never prunes. Replaced packs get `pack-<sha>.drop`, which `state()` skips; a later run deletes `.idx`, `.pack`, then `.drop` once the marker is older than `--grace`. Indexless packs are deleted only after 24h (`unindexedAge`), whatever the grace, because a push in flight has its `.pack` before its `.idx`. No lock: each run drops packs only after its merged pack is uploaded and verified (`TestConcurrentGC`).
  - **Prune** (`s3/prune.go`, `ogit storage prune [--expire 336h] [--dry-run]`, a separate command so a gc cron line can't enable it): packs older than `--expire` (by S3 LastModified; packs are immutable, so it bounds their objects' age) are rewritten with only the objects reachable from HEAD, every ref, **or any object in a younger pack** (in-flight pushes whose refs are not updated yet, and gc output). Then the old packs are dropped like gc's. A missing object in the walk aborts (`TestPruneAbortsOnMissingObject`). Objects merged by gc get a fresh pack, so gc restarts their expiry.
  - **Cache** (`infrastructure/storage/cache`, `storage.s3.cache.*`): `memory` LRU (default, 256 MiB), `redis` (shared; 250ms timeouts, no retries, skipped for 30s after an error so an outage costs nothing) or `none`. Keys are `bucket/key#block`. That is safe only because packs are immutable; never cache refs or HEAD.
  - **Refs are compare-and-swap**: `CheckAndSetReference` uses `If-Match` on the ETag, `CreateReference` uses `If-None-Match: *`. `GuardedReceivePack` (`helpers/git/receive_pack.go`) makes go-git's receive-pack pass the client's old value to them, which it otherwise ignores. MinIO (and gofakes3) ignore `If-Match` on DELETE, so `RemoveReferenceIf` compares first and a concurrent delete race remains there.
  - `TestS3RequestBudget` fails if a push, clone or fetch of a 300-commit repo needs more than 25 requests (counted by `s3test.StartCountingFake`).

## Gotchas

- **The web UI catch-all** (`setupWebUI`) answers every GET/HEAD that no earlier route matched with `index.html` (200), except `/api/...` (JSON 404) and missing `/assets/...` (404). Register new routes before it, in `SetupRoutes`. It sets a strict CSP (`default-src 'self'`): the app must not use inline scripts or third-party origins.
- **fiber-oapi**: unauthenticated `/api/v1` requests get **400** `"authentication required"`, not 401. Its validator is a private global, so custom tags such as `slug` cannot be registered (an unknown tag makes every request 500).
- **GORM `default:` tags** drop zero values on insert, so the column default wins. This made every repo private (`IsPrivate` had `default:true`). Don't put defaults on booleans that callers set to false; apply defaults in the API layer instead (`is_private` is `*bool`, defaulting to true).
- **IDs** are set in application code (`utils.UUIDv4()`) or in `BeforeCreate`. An empty string ID inserts fine on SQLite and then breaks the next insert.
- **Postgres differs from SQLite**: JSON columns come back as `[]byte`, not `string`. `sql.Scanner` implementations must handle string, []byte and nil and return errors. A panic inside `Scan` deadlocks the connection (`database/sql` still holds the rows lock), so the request hangs instead of failing. That is how every Postgres login hung (`JSONB.Scan`). Run the Postgres e2e suite for anything touching persistence or migrations.
- **Fetch negotiation and pushes are not go-git's** (`infrastructure/helpers/git/upload_pack.go`, `no_thin.go`). go-git's server does no negotiation, so `ServeUploadPack` implements it: plain protocol over SSH (one stateful stream), and `multi_ack_detailed` over HTTP. HTTP is stateless and a plain-mode client does not resend acknowledged commons; `AdvertiseUploadPackHTTP` advertises it. Receive-pack advertises `no-thin`: go-git cannot resolve thin packs ("reference delta not found"), which every real push against existing history produces. `TestFetchNegotiation` (300 commits, unpushed commits, unrelated history) and `TestPushDeltaAgainstExistingObjects` use the real git client and catch regressions that go-git clients and small test repos never hit.
- **Push size** (`helpers/git/push_limit.go`, `git.max_push_size`, 2 GB, HTTP and SSH): `SpoolPack` stages the pack in a temp file within the limit before go-git reads it, because go-git writes packs as it reads and closes its writer even on error (a cut-short push would leave a partial pack). Over the limit the client gets a report (`RefusedReport`); over HTTP the rest of the body is discarded first (up to the limit again) because curl only reads the answer after sending. git probes large HTTP pushes with a lone flush-pkt, answered with an empty 200. `TestLargePushes` uses the real git client.
- **Git over SSH** (`interfaces/ssh`): x/crypto/ssh server; user `git` only, key identified by SHA256 fingerprint (`ssh_key.fingerprint`, unique: user key or deploy key), then `AuthApp.IdentifySSHKey` / `AuthorizeSSH` mirror the HTTP rules. Unlike HTTP the stream stays open, so: send `exit-status` **before** closing the channel (otherwise git says "remote end hung up"); a client with nothing to fetch/push sends only a flush-pkt (`isFlush`); a delete-only push sends no pack, so `req.Packfile` must be nil (`helpergit.OnlyDeletes`, also on HTTP, where go-git otherwise fails with "empty packfile") or the server blocks reading one. All three are covered by `TestGitOverSSH` with the real `git` client; keep testing SSH changes with the real CLI (`gitCLI` helper), not only go-git.
- **SQLite does not enforce foreign keys** here (the `foreign_keys` pragma is off), so `ON DELETE CASCADE` only works on postgres. Delete dependent rows explicitly in a transaction (see `groupPers.Delete`).
- **Enum strings** in `domain` must match the migration's CHECK/enum values (`TokenRepo` = `"repository"`).
- **Logging**: never log tokens, JWTs or passwords. `GormLogger.ParamsFilter` keeps bound values out of SQL logs; keep it.
- `helperError.Catch` maps any unique-constraint failure to `gorm.ErrDuplicatedKey`, so "already exists" messages can hide a different constraint.
- `.dev/*.sh` are curl helpers for a running server; their password satisfies the default policy.

## Tests

- End-to-end tests live in `interfaces/cli/server/*_test.go`. `startTestServer(t, opts...)` builds the real app (sqlite in a temp dir, migrations, routes, random port). Helpers: `registerAndLogin`, `createRepo`, `createToken`, `post`/`get`, `clone`, `commitAndPush` (go-git client).
- Repository URLs in tests: `srv.url+"/owner/slug.git"`, `gitCLI.url("owner/slug")`, `repoAPI("owner/slug")` for API paths. Test usernames must be valid namespaces (not `api`, `admin`, ...). Namespace rules: `namespaces_test.go`.
- `testGitHTTPAuthorization` runs on local storage, fake S3 and MinIO (integration tag). New git behaviour should go in there so it is checked on every backend.
- S3 test endpoints come from `infrastructure/storage/s3/s3test`: `StartFake` (gofakes3), `StartMinIO` (`//go:build integration`), `Configure(cfg, ep)`, `NewStorage`. Tests in package `s3` must use package `s3_test` (`s3test` imports `s3`).
- MinIO image: `cgr.dev/chainguard/minio` pinned by digest, because `minio/minio` is no longer pullable from Docker Hub or quay.io.
- nektos/act v0.2.89 (runner only) raised go-git to 5.16.5, go-billy to 5.9 and x/crypto to 0.50; it keeps `go 1.25.1`.
- Pinned test deps: gofakes3 v1.0.0, testcontainers-go v0.40.0 (and its redis module), grpc-gateway/v2 v2.16.0, go-redis v9.22.0 (v9.23 needs Go 1.26). Newer ones (or `go mod tidy` resolving @latest) can raise the `go` directive and upgrade the AWS SDK. Check `go.mod` after any `go get`/`tidy`.
- Speed: `main_test.go` sets `application.PasswordCost` to `bcrypt.MinCost` (at the default, every hash takes about 0.5s under `-race`). Keep any new password hashing on `PasswordCost`. Only the three heaviest tests (`TestFetchNegotiation`, `TestS3RequestBudget`, `TestLastOwnerConcurrentDemotion`) call `t.Parallel()`. Before adding more, check for process globals: goose's are why `RunMigration` takes a mutex.
- For security fixes, check that reverting the fix makes the test fail on an assertion, not on `log.Fatal` or a build error.
- Timeouts in tests are for hangs, not speed: real git and ssh commands get `gitTimeout` (3 minutes; a 24 MB SSH clone from fake S3 once took over 30s on CI) and waits for goroutines (emails) use `asyncWait` (10s) in `assert.Eventually`. Use them for new tests rather than tight literals. CI steps that run the e2e package set `-timeout` explicitly (the package outgrew go test's default 10 minutes).

## Docker

The release workflow builds a static binary (`CGO_ENABLED=1`, `-extldflags -static`) into `bin/app`. The Dockerfile copies it into Alpine, and `entrypoint.sh` (POSIX `sh`, since Alpine has no bash) runs `migration` and then `server` with `/config/config.yaml`.
